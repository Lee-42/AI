# Agent 编程规范

## 代码注释

后续编写或修改代码时，默认添加简明扼要的中文注释。

注释原则：

- 只解释关键意图、设计边界、业务规则和容易误解的地方。
- 不逐行解释显而易见的语法。
- 注释要短，优先说明“为什么这样写”，而不是重复“代码正在做什么”。
- 涉及第三方 API、供应商兼容、环境变量、错误处理、数据校验、流式输出、多模态输入等关键逻辑时，应补充必要中文注释。
- 示例代码中的注释要服务教学，帮助学习者理解核心概念。

推荐：

```ts
// 统一从这里选择供应商，避免业务代码直接绑定某个模型平台。
const provider = getDefaultProvider();
```

不推荐：

```ts
// 定义一个变量 provider。
const provider = getDefaultProvider();
```

## 代码风格

- 保持代码结构清晰，优先使用小而明确的函数。
- 示例项目优先保证可读性，再考虑复杂抽象。
- Provider、配置、业务示例应分层放置，避免示例代码直接散落大量供应商细节。
- 环境变量、API Key、模型名等配置不要硬编码在业务逻辑中。
- 修改代码后尽量运行类型检查或对应测试。

# 第 09 节：Rerank、上下文组装、Token 预算与引用设计

日期：2026-08-05  
状态：已获用户确认

## 1. 目标

在现有“查询理解 + Metadata Filter + 混合召回”之后，增加一条可测试、可替换且默认不产生云端费用的证据处理流水线：

```text
混合召回候选
  -> Rerank
  -> 有效性与冲突判断
  -> Token 预算分配
  -> 上下文组装
  -> 结构化引用
  -> KnowledgeRetrievalResult
```

本节负责把“可能相关的候选”加工成“允许 LLM 使用的证据”。它不负责接入真实在线 LLM，也不把课程默认实现绑定到某一家 Rerank 或 tokenizer 服务。

## 2. 组件边界

### 2.1 CandidateReranker

定义可替换接口，输入查询和混合召回候选，输出带有重排分数、排序和原因码的候选。

课程默认实现采用确定性规则，综合：

- 查询词覆盖和标题命中；
- Dense 与 Lexical 两路排名是否相互印证；
- 明显否定或语义反向线索，例如查询“质量问题”时降低“非质量问题”的排名。

默认实现的目的不是替代 Cross-Encoder，而是让本地测试稳定、免费且能观察完整数据流。将来接入在线 Rerank 时，只替换接口实现。

### 2.2 EvidenceGate

只允许 `active`、租户匹配、通过阈值且未被冲突规则阻止的证据进入上下文。

政策冲突不依赖字符串或数值猜测。知识源清单增加可选 `conflictGroup`，同一业务主题下存在多个相互矛盾的有效来源时返回 `conflicting`，停止生成答案。例如两个不同版本的“上门取件费”政策共享同一冲突组。

### 2.3 TokenCounter 与 ContextAssembler

`TokenCounter` 是可替换接口。课程默认使用保守的离线近似计数器，生产环境可替换为与实际模型匹配的精确 tokenizer。

上下文可用预算按以下思路计算：

```text
模型上下文窗口
- 系统提示词
- 用户问题
- 协议包装开销
- 最大输出预留
- 安全余量
= 证据可用预算
```

`ContextAssembler` 按 Rerank 顺序装入完整切片。放不下的切片被明确记录为 `budget_exceeded`，不从中间截断，以避免语义和引用边界被破坏。

### 2.4 结构化引用

每条上下文证据保留：

- `sourceId`
- `chunkId`
- `version`
- `title`
- `content`

模型只能引用真正进入上下文的证据。已有 Orchestrator 继续校验模型返回的来源 ID；未知来源或因预算被排除的来源都不能成为有效引用。语音回答不朗读内部 ID，Web UI 可以使用结构化字段展示来源。

## 3. 两类 Token 计数方式的区别

| 维度 | 保守近似 TokenCounter（课程默认） | 精确 tokenizer（生产可选） |
| --- | --- | --- |
| 结果 | 估算，主动留有余量 | 与指定模型分词规则一致或非常接近 |
| 模型绑定 | 不绑定供应商和模型版本 | 绑定模型、编码器及其版本 |
| 运行条件 | 完全离线，无额外费用 | 可能需要额外依赖、模型文件或供应商能力 |
| 测试稳定性 | 高，便于构造固定预算测试 | 模型或 tokenizer 升级后结果可能变化 |
| 适用阶段 | 教学、单元测试、早期开发、兜底 | 生产发布前的精确容量控制和成本核算 |
| 主要风险 | 估算过多会少放证据；估算过少可能溢出 | 配置错模型版本会产生“看似精确”的错误预算 |

两者共享同一接口。生产环境的原则是：使用与实际推理模型完全匹配的 tokenizer，并保留安全余量；精确计数也不能消除提示模板变化和供应商协议开销带来的风险。

## 4. 状态与失败策略

- 没有候选通过阈值：返回 `none`，不调用 LLM。
- 存在显式政策冲突：返回 `conflicting`，不调用 LLM。
- 预算不足以放入任何完整证据：返回 `none`，并记录预算原因。
- 至少有一条有效证据进入上下文：返回 `sufficient`。
- 模型引用未进入上下文的来源：由 Orchestrator 拒绝该引用或拒绝该回答。

流水线不隐藏降级行为。Rerank 原因、预算使用量、入选和排除列表应能够被调试脚本和测试观察，但不把内部评分细节暴露给终端用户。

## 5. 验证场景

本节使用离线 fixture 完成以下验证：

1. 查询“东西坏了怎么办”时，“非质量问题”候选被降权，真正的质量售后政策优先。
2. 查询“上门取件费”时，两个显式冲突的政策触发 `conflicting`，不生成回答。
3. 人为设置较小预算时，只装入排名靠前的完整切片，其余候选记录为预算排除。
4. 引用集合只包含实际进入上下文的证据。
5. 相同输入下离线 Rerank、Token 估算和上下文结果完全可复现。

## 6. 教学范围

教学文档以理解闭环为目标，不强制压缩成四个知识点。预计组织为五个紧凑部分：

1. 为什么召回之后还需要 Rerank；
2. 如何判断可回答、冲突与拒答；
3. Token 预算和两类计数器的区别；
4. 上下文组装与引用闭环；
5. 运行实验与企业落地建议。

## 7. 非目标

- 本节不调用收费的在线 Rerank、Tokenizer 或 LLM API。
- 本节不实现新的客服对话 UI。
- 本节不完成下一章的真实 LLM Runtime 接线。
- 本节不依赖模糊文本推断政策冲突；冲突属于知识治理元数据。

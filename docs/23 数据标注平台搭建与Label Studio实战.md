## 01 什么是数据标注

### 本节目标

学完这一节，应该能够：

- 用自己的话解释什么是数据标注；
- 区分原始数据、标签、标注规则和已标注数据；
- 识别分类、框选、文本片段、关系、排序等常见标注结果；
- 说清楚一项标注任务从定义到验收的基本流程；
- 判断一批标注数据是否准确、一致、完整并且可追溯。

### 1. 从一个具体问题开始

假设我们收集了三条电商评论：

```text
物流很快，包装也很好。
衣服有破损，准备退货。
颜色和图片基本一样，但尺码有点偏小。
```

人可以直接理解这些句子的态度，但计算机看到的首先只是一串字符。如果我们要整理一批“评论
情绪”样本，就需要按统一规则为每条评论补充答案：

| 原始评论 | 标签 |
| --- | --- |
| 物流很快，包装也很好。 | 正向 |
| 衣服有破损，准备退货。 | 负向 |
| 颜色和图片基本一样，但尺码有点偏小。 | 混合 |

这里的“正向、负向、混合”不是原文自带的信息，而是标注者根据任务目标和规则添加的结构化
信息。这个过程就是数据标注。

### 2. 数据标注的定义

数据标注可以理解为：

```text
按照事先定义的任务和规则，
为原始数据添加机器可以读取的语义信息或参考答案。
```

可以把它写成一条简单的转换链路：

```text
原始数据 + 标注任务 + 标注规范
                  ↓
              标注过程
                  ↓
         原始数据 + 标注结果
                  ↓
              已标注数据
```

原始数据可以是文本、图片、音频、视频，也可以是多种模态的组合。标注结果也不一定只是一个
类别，它还可以是坐标、文本区间、实体关系、答案、评分或多个结果的偏好顺序。

数据标注的重点不只是“给数据贴一个名字”，而是把人的判断转换成结构清晰、标准统一、可以被
程序处理的数据。

### 3. 四个容易混淆的概念

| 概念 | 含义 | 示例 |
| --- | --- | --- |
| 原始数据（Data） | 尚未附加任务答案的数据对象 | 一条评论、一张街景图片、一段客服录音 |
| 标签（Label） | 预先定义的类别或答案值 | `正向`、`汽车`、`需要转人工` |
| 标注（Annotation） | 按规则为某个样本生成标注结果的动作，也可指具体结果 | 把评论判为正向、在图片中框出汽车 |
| 已标注数据（Labeled Data） | 原始数据与标注结果组成的完整记录 | 评论正文及其情绪标签 |

“标签”和“标注结果”有时会被混用，但严格来说，标注结果可以比单个标签复杂。例如目标检测的
结果不仅包含 `汽车` 这个类别，还包含汽车在图片中的边界框坐标。

元数据也不一定是标注。文件名、上传时间和拍摄设备通常只是描述数据来源；只有当某项信息是
针对任务目标、按照规则产生的判断时，才是这项任务中的标注结果。

### 4. 常见的数据标注类型

#### 4.1 分类标注

分类是从预先定义的标签集合中为整个样本选择一个或多个类别。

```text
评论：物流很快，包装也很好。
标签：正向
```

常见形式包括：

- 单标签分类：正向、负向、混合三选一；
- 多标签分类：一条工单同时属于“退款”“物流”和“投诉”；
- 层级分类：先选择“售后问题”，再选择“退货退款”。

#### 4.2 文本片段与序列标注

这类任务不是判断整段文本，而是找出其中具有特定意义的片段。

```text
文本：张三计划周五去上海出差。
人名：[张三]
时间：[周五]
地点：[上海]
```

命名实体识别就是典型的文本片段标注。结果通常包含标签、片段内容以及字符起止位置。

#### 4.3 图片分类、框选与分割

对图片可以有不同精度的标注：

| 类型 | 回答的问题 | 典型结果 |
| --- | --- | --- |
| 图片分类 | 整张图片里主要是什么？ | `猫` |
| 目标检测 | 目标在哪里、是什么？ | `猫 + 矩形框坐标` |
| 图像分割 | 目标精确覆盖哪些像素？ | `猫 + 像素区域` |
| 关键点 | 目标的重要位置在哪里？ | `眼睛、鼻子、关节坐标` |

所以“给图片标一个猫”仍然不够明确。必须先说明任务要的是整图类别、边界框、轮廓还是关键点。

#### 4.4 音频与视频标注

音频可以标注转写文本、说话人、情绪和事件发生的时间区间；视频还会涉及连续帧中的目标轨迹、
动作类别和事件起止时间。

例如：

```text
00:03.200 - 00:05.800
说话人：客户
转写：我想查询一下退款进度。
意图：查询退款
```

#### 4.5 关系、评分与偏好标注

有些任务需要表达多个对象之间的关系，或比较多个候选结果：

```text
实体关系：张三 --就职于--> 某公司
回答评分：正确性 4 / 5
偏好排序：回答 B 优于回答 A
```

在大模型场景中，问题与理想回答、两份回答之间的偏好、回答中的事实错误位置，都可以成为标注
结果。无论形式如何变化，本质仍是按照规则把人的判断转成结构化记录。

### 5. 一项标注任务由什么组成？

一个完整的标注任务至少需要六个要素：

| 要素 | 要回答的问题 |
| --- | --- |
| 数据对象 | 要标注什么？文本、图片还是音视频？ |
| 任务目标 | 希望标注者判断什么？ |
| 标签体系 | 有哪些合法标签或结果类型？ |
| 标注规范 | 每个标签如何定义？边界情况如何处理？ |
| 标注角色 | 谁负责初标、复核和仲裁？ |
| 质量标准 | 怎样才算合格？如何抽检和返工？ |

如果只把数据和几个标签发给标注者，没有说明判断规则，不同人就会凭个人理解工作。最后即使
所有样本都“标完了”，结果也可能互相矛盾。

例如评论“还行吧，就是有点贵”应该标为中性、负向还是混合，仅凭直觉没有唯一答案。项目必须
在标注规范中约定：情绪针对商品整体还是价格维度；同时出现褒贬时如何处理；信息不足时能否
选择“无法判断”。

### 6. 数据标注的基本流程

一项可靠的标注工作通常按下面的顺序推进：

```text
明确业务问题
  ↓
确定数据对象和标注任务
  ↓
设计标签体系与标注规范
  ↓
用少量样本试标
  ↓
分析分歧并修改规范
  ↓
批量标注
  ↓
复核、抽检与仲裁
  ↓
导出、记录版本并验收
```

试标非常重要。它可以提前发现标签定义重叠、边界情况遗漏、界面操作困难以及数据本身不适合
当前任务等问题。发现这些问题后，应先修正规范和标签体系，再开始大规模标注。

标注平台的作用，是帮助团队导入任务、配置界面、分配工作、记录结果、复核质量和导出数据。
平台能规范流程，但不会自动替团队定义正确的业务目标和标注规则。

### 7. 人工、自动与人机协同标注

按照结果产生方式，可以把标注分为三类：

| 方式 | 工作模式 | 特点 |
| --- | --- | --- |
| 人工标注 | 人从头判断每个样本 | 判断灵活，但速度和成本受人工限制 |
| 自动标注 | 规则或模型直接产生结果 | 速度快，但错误可能被成批放大 |
| 人机协同 | 模型预标注，人负责确认或修改 | 常能提高效率，但仍需质量控制 |

模型预标注不等于真实答案。若标注者习惯性接受模型建议，就可能产生“自动化偏见”，让模型原有
错误进入最终数据。人机协同项目仍要保留人工复核、抽样检查和修改记录。

### 8. 什么样的标注才算好？

高质量标注至少需要关注四个维度：

- 准确性：结果符合事实和标注规范；
- 一致性：相似样本在相同规则下得到相同判断，不同标注者对规则理解一致；
- 完整性：该标的对象都已标注，必填字段没有遗漏；
- 可追溯性：能够知道谁在何时按哪个规范版本做了标注，以及之后是否被修改。

数量多不等于质量高。如果标签定义含糊、数据重复、类别严重失衡或标注错误，大量数据只会把
问题放大。

实践中常让多个标注者独立处理一部分相同样本，再比较结果。如果分歧很多，不能简单认为其中
一个人“标错了”，还要检查任务目标是否含糊、标签是否重叠、规范是否缺少边界案例。

### 9. 常见误区

#### 误区一：数据标注就是随手贴标签

标签必须服务于明确任务，并遵守统一规范。没有任务定义的“随手分类”很难形成可复用的数据。

#### 误区二：标签越细越专业

标签越细，标注难度和分歧通常越大。如果业务和数据无法可靠地区分这些类别，过细的标签体系
反而会降低质量。

#### 误区三：标完一次就结束了

业务定义、数据分布和质量要求都会变化。标注数据、标签体系和规范都应该有版本，并允许复核、
返工和更新。

#### 误区四：用了标注平台就能保证质量

平台负责承载流程，质量仍取决于任务设计、规范、人员培训、复核机制和验收标准。

#### 误区五：模型生成的标签一定比人更客观

模型会继承训练数据和提示词中的偏差，也可能在相似样本上稳定地产生同一种错误。自动结果必须
经过验证，不能仅因其格式整齐就视为正确。

### 10. 一个最小标注规范示例

下面是一份简化的电商评论情绪规范：

| 标签 | 定义 | 示例 |
| --- | --- | --- |
| 正向 | 对商品或服务表达明确满意 | “质量很好，还会回购。” |
| 负向 | 对商品或服务表达明确不满 | “鞋底开胶了，非常失望。” |
| 混合 | 同时包含明确的正向和负向评价 | “款式好看，但是做工粗糙。” |
| 无法判断 | 没有态度，或上下文不足 | “昨天收到货了。” |

还需要补充边界规则：

- 只评价物流时，是否纳入商品评论情绪；
- 反讽、表情符号和网络用语怎样判断；
- 一条评论涉及多个商品时如何处理；
- 标注者不确定时是选择“无法判断”，还是提交复核；
- 文本为空、乱码或语言不支持时怎样处理。

这说明真正可执行的标注规范不仅要列出标签，还要定义标签边界和异常处理方式。

### 11. 本节练习

#### 练习一：识别标注类型

判断下列任务分别属于哪种标注类型：

1. 判断一封邮件是正常邮件还是垃圾邮件；
2. 在合同中找出甲方、乙方、金额和签署日期；
3. 在道路图片中框出每一辆汽车；
4. 比较两份客服回答，选择更准确的一份；
5. 把一段会议录音转成文字，并区分不同说话人。

参考答案：

1. 单标签分类；
2. 文本片段或命名实体标注；
3. 目标检测；
4. 偏好标注；
5. 音频转写与说话人标注。

#### 练习二：发现任务缺口

现在有一个任务说明：

```text
请把用户评论标成“好评”或“差评”。
```

想一想它至少缺少哪些规则。

可以从这些问题检查：中性评论怎么办；同时有褒有贬怎么办；评价物流但没有评价商品怎么办；
反讽怎样判断；无内容或乱码怎么办；不确定时由谁复核。

#### 练习三：用一句话复述

不要看前文，尝试补全：

```text
数据标注是按照 ______，为 ______ 添加 ______ 的过程。
```

一种合格的回答是：

```text
数据标注是按照预先定义的任务和规范，为原始数据添加机器可读的语义信息或参考答案的过程。
```

### 本节小结

本节最重要的认识是：

```text
数据标注不是简单贴标签，
而是把人的判断按照统一规则转换成机器可处理的数据。
```

一项完整的标注工作需要明确数据对象、任务目标、标签体系、标注规范、人员角色和质量标准。
标注结果可以是类别，也可以是文本区间、坐标、关系、评分、答案或偏好顺序。平台可以提高协作
效率，但无法替代任务定义和质量治理。

## 02 标注出来的数据到底是做什么用的？

### 本节目标

学完这一节，应该能够：

- 解释标注数据为什么能为模型提供学习信号；
- 区分训练集、验证集和测试集的职责；
- 说清不同标注形式能够支持哪些 AI 任务；
- 理解 SFT 数据、偏好数据和评测数据在大模型中的不同作用；
- 避免“所有标注数据都应该拿去训练”这一常见误解。

### 1. 核心答案：给机器提供可比较的参考

上一节把数据标注定义为“为原始数据添加机器可读的语义信息或参考答案”。那么这些参考答案
有什么用？最核心的作用是：

```text
让程序知道一个样本期望得到什么结果，
从而可以学习、验证或评价模型的行为。
```

继续使用电商评论的例子：

```text
输入：物流很快，包装也很好。
标签：正向
```

只有评论正文时，模型可以阅读或生成内容，却不知道当前任务要求它把这条评论判成哪一类。
加入“正向”标签后，这条记录才成为一个带参考答案的监督样本。

标注数据并不只有训练这一种用途。同一套高质量标注数据经过合理划分后，可以进入模型生命周期
的不同环节：

| 环节 | 标注数据的作用 | 是否更新模型参数 |
| --- | --- | --- |
| 训练 | 提供学习目标，让模型根据错误调整参数 | 是 |
| 验证 | 比较不同参数、配置或训练轮次的效果 | 否 |
| 测试 | 在训练结束后评价最终模型 | 否 |
| 上线监控 | 检查真实业务中的效果是否下降 | 通常否 |
| 迭代改进 | 收集失败案例，形成下一轮训练或评测数据 | 进入下一轮时可能会 |

所以，更准确的说法是：

```text
标注数据是模型学习和质量评价的共同基础，
而不只是“喂给模型训练的数据”。
```

### 2. 标签如何变成模型的学习信号？

以情绪分类模型为例，一条训练记录包含输入 `x` 和参考标签 `y`：

```text
x = “衣服有破损，准备退货。”
y = “负向”
```

训练时会发生下面的过程：

```text
带标签样本
  ↓
模型读取评论并给出预测
  ↓
预测结果与参考标签比较
  ↓
计算损失：这次预测错得有多大
  ↓
反向传播并调整模型参数
  ↓
在大量样本上重复
```

假设模型第一次预测为：

```text
正向：0.60
负向：0.30
混合：0.10
```

参考标签却是“负向”，损失函数就会给出较大的错误信号。训练算法据此调整参数，让模型以后
遇到“破损”“退货”等相似表达时，更有可能输出负向。

这里要避免一种误解：模型通常不是把每一条“评论 → 标签”原样存进一个答案表。训练希望它从
大量样本中学习能够泛化的模式，使它面对从未见过的新评论时也能做出合理判断。

训练与推理也要明确区分：

| 阶段 | 模型看到什么 | 标签做什么 |
| --- | --- | --- |
| 训练 | 输入和参考标签 | 用来计算误差、更新参数 |
| 推理 | 新输入 | 通常没有标签，模型自己预测 |

如果线上新数据已经有可靠答案，就不需要模型再预测；正因为真实答案未知，才需要训练好的模型
进行推理。

### 3. 为什么要分成训练集、验证集和测试集？

如果用同一批样本训练又评价，就像让学生提前背下考试原题，再用原题成绩证明他掌握了知识。
模型可能只记住训练样本，却不能处理新数据。

因此，已标注数据通常会被划分为：

| 数据集 | 主要用途 | 使用原则 |
| --- | --- | --- |
| 训练集（Train Set） | 更新模型参数 | 可以被模型反复学习 |
| 验证集（Validation Set） | 选择超参数、模型版本和停止时机 | 可以用于选择方案，但不直接训练参数 |
| 测试集（Test Set） | 给最终方案做相对客观的验收 | 在方案确定前不应反复查看和调参 |

例如有 10,000 条评论，可以按 8:1:1 划分为 8,000 条训练数据、1,000 条验证数据和 1,000 条
测试数据。这只是示例，不是所有项目都必须使用的固定比例。数据规模、类别数量、时间分布和业务
风险都会影响实际划分方式。

划分时还要防止数据泄漏：

- 同一条评论及其轻微改写不能同时进入训练集和测试集；
- 同一视频切出的相邻帧不宜随机分到不同集合；
- 同一个用户或同一事件产生的高度相关样本，可能需要按用户或事件整体划分；
- 如果目标是预测未来业务，应考虑按时间划分，用较早数据训练、较新数据测试。

测试集一旦被反复用来挑选 Prompt、阈值或模型，它实际上就承担了验证集的作用，测试结果也会
变得过于乐观。此时应该保留新的、未参与方案选择的数据做最终验收。

### 4. 不同标注形式支持不同模型能力

标注的结构决定了模型能够从样本中学习什么任务：

| 原始数据 | 标注结果 | 支持的典型能力 |
| --- | --- | --- |
| 评论文本 | 正向、负向、混合 | 文本分类、情绪识别 |
| 句子 | 实体类别及字符位置 | 命名实体识别、信息抽取 |
| 图片 | 类别 | 图片分类 |
| 图片 | 类别及矩形框坐标 | 目标检测 |
| 图片 | 目标的像素区域 | 图像分割 |
| 音频 | 转写文本及时间戳 | 语音识别、字幕对齐 |
| 问题 | 理想答案 | 问答、指令遵循 |
| 一个问题与多个回答 | 评分或偏好顺序 | 回答排序、偏好对齐 |

同一份原始数据可以服务于不同任务，但需要不同的标注。例如同一张道路图片：

```text
只标“有汽车”       -> 可以训练图片分类
框出每辆汽车        -> 可以训练目标检测
勾画汽车精确轮廓    -> 可以训练图像分割
标出连续帧中的轨迹  -> 可以训练目标跟踪
```

这再次说明，开始标注之前必须先明确要解决什么问题。任务定义不同，需要的数据结构、标注成本和
模型输出都会不同，不能在标完之后才临时决定用途。

### 5. 标注数据在大模型中怎样使用？

大模型的数据流程比普通分类模型更复杂，但底层逻辑仍然是用参考结果约束模型行为。

首先要区分预训练和人工标注：大模型预训练通常会从海量文本中构造“预测下一个 Token”的学习
目标，这类目标可以由文本自身产生，不需要人工逐条写标签，通常称为自监督学习。人工标注更多
出现在后续训练和评价阶段。

| 数据形式 | 简化示例 | 主要用途 |
| --- | --- | --- |
| 指令—回答数据 | `用户问题 → 理想回答` | 监督微调（SFT），学习按指令回答 |
| 偏好数据 | `同一问题下，回答 A 优于 B` | 偏好对齐，让输出更符合人类期望 |
| 评分或批注数据 | `事实性 2/5，遗漏关键条件` | 训练评价模型或分析失败类型 |
| 工具调用数据 | `用户请求 → 工具及参数 → 最终回答` | 学习何时以及怎样调用工具 |
| 标准评测集 | `问题 → 参考答案/评分规则` | 比较微调前后或不同模型的能力 |

以 SFT 为例：

```text
指令：把下面的评论判断为正向、负向或混合。
输入：款式很好看，不过拉链很难用。
理想输出：混合
```

它教给模型的不只是一个事实，还包含任务格式、输出边界和回答风格。偏好数据则不一定提供唯一
标准答案，而是告诉模型在两个候选回答中哪个更符合准确、安全或有帮助等要求。

还要注意，少量人工问答不适合承担所有“给模型补充最新知识”的任务。频繁变化、需要引用来源
的业务知识通常更适合通过 RAG 或工具在推理时提供；标注数据更适合用来教行为、格式、判断边界，
以及评价模型是否正确使用这些知识。

### 6. 并非所有标注数据都应该拿去训练

标注数据还可以直接用于模型之外的工作：

| 用途 | 例子 |
| --- | --- |
| 建立评测基准 | 固定一批人工确认的客服问答，用来比较不同模型和 Prompt |
| 监控线上质量 | 定期人工复核线上预测，观察准确率是否随时间下降 |
| 业务分析 | 统计投诉原因、商品缺陷类型和高频客户意图 |
| 规则与流程设计 | 从标注案例中提取必须转人工或必须拒绝的边界 |
| Few-shot 示例 | 在 Prompt 中提供少量标准输入输出，帮助模型理解任务 |
| 发现下一轮数据 | 找出模型最不确定、最容易出错的样本，优先送去标注 |

评测数据尤其不能随意混入训练集。一旦模型学习过评测答案，再用这批数据测效果，得到的分数就
不能代表它处理新样本的真实能力。

有些标注还直接服务于业务，而不是训练模型。例如客服团队可以把工单标为“退款、物流、质量”，
用来分配人员和统计问题。以后即使把这些数据用于建模，也应先检查原有标签的定义、质量和合规
范围是否满足新的目标。

### 7. 数据质量如何影响最终效果？

标注是学习目标。如果目标本身错误或互相矛盾，模型就会学到错误模式：

```text
错误标签      -> 模型被奖励去做错误预测
规则不一致    -> 相似输入对应不同答案，学习信号互相冲突
类别不平衡    -> 模型倾向样本数量最多的类别
样本不代表线上 -> 离线分数高，真实业务效果差
训练测试泄漏  -> 评测分数虚高
```

例如 90% 的评论都被标成正向，一个始终预测正向的模型也能达到 90% 准确率，但它可能完全识别
不出真正重要的差评。此时不能只看总体准确率，还要分别检查每个类别的表现和业务代价。

生产环境中的数据分布也会变化。新的商品、用户表达和业务规则出现后，旧标注集可能不再能代表
真实场景。因此标注数据通常会形成持续迭代的闭环：

```text
标注初始数据
  ↓
训练并离线评测
  ↓
上线模型
  ↓
抽检真实预测与收集失败案例
  ↓
复核、补标或修正规范
  ↓
更新训练集与评测集
  ↓
重新训练和验收
```

这个闭环中，数据集、标签体系和标注规范都应该记录版本。否则模型效果变化时，很难判断原因是
代码、模型、数据还是规则发生了改变。

### 本节练习

1. 有 6,000 条已经标注的商品评论。以下操作分别应该主要使用训练集、验证集还是测试集？

   - 更新情绪分类模型的参数；
   - 比较学习率 `1e-4` 和 `2e-5` 哪个更好；
   - 在方案完全确定后报告最终效果。

   参考答案依次是：训练集、验证集、测试集。

2. 判断下面说法是否正确：

   - “只要人工标过，就可以把全部数据同时用于训练和测试。”——错误，会产生数据泄漏；
   - “验证集不更新参数，所以可以无限次调试而没有影响。”——错误，反复选择会让方案过度适应验证集；
   - “目标检测的标签只有物体类别。”——错误，至少还需要物体位置；
   - “大模型的所有训练文本都需要人工写标签。”——错误，预训练通常大量使用自监督目标；
   - “标注数据也可以只用于评测，不进入训练。”——正确。

3. 用自己的话解释下面这条链路中，标签在哪一步发挥作用：

```text
输入样本 → 模型预测 → 与标签比较 → 计算损失 → 更新参数
```

合格答案应该指出：标签是参考目标，用来衡量预测误差；训练算法根据误差信号调整参数，而推理新
样本时通常没有标签。

### 本节小结

标注数据最核心的价值，是为机器提供可以比较的参考答案。它可以在训练阶段产生误差信号，也可
以在验证、测试和上线监控阶段衡量模型质量。

需要记住三组边界：

```text
训练集：用来学习
验证集：用来选择方案
测试集：用来最终验收

训练：输入和标签共同参与，参数会更新
推理：只有新输入，模型给出未知答案

人工标注：常用于监督微调、偏好对齐和评测
自监督数据：可以从原始文本自身构造学习目标
```

不同任务需要不同标注结构，错误、冲突、失衡或泄漏的数据都会影响模型效果。高质量标注数据既
是训练材料，也是可靠评测和持续迭代的基础。

下一节将开始安装 Label Studio，把前两节的概念落实到一个可以创建、分配、标注和导出任务的
平台中。

## 03 Label Studio 环境安装

### 本节目标

学完这一节，应该能够：

- 在 SaaS、`pip` 和 Docker 三种方式之间做出选择；
- 使用 Docker 启动一个数据可持久化的本地 Label Studio；
- 使用 Python 虚拟环境完成独立安装；
- 完成首次登录并验证服务是否正常；
- 处理端口占用、Docker 未启动、Python 依赖冲突和数据丢失等常见问题。

本节安装命令依据 Label Studio 的[官方安装文档](https://labelstud.io/guide/install.html)和
[官方快速开始文档](https://labelstud.io/guide/quick_start)整理。

### 1. 选择路线并检查本机环境

Label Studio 不只有一种运行方式：

| 方式 | 是否本地安装 | 数据和服务在哪里 | 适合场景 |
| --- | --- | --- | --- |
| Starter Cloud / Enterprise Cloud | 否 | 官方云端 | 快速体验、团队协作 |
| `pip` 安装 Community Edition | 是 | 当前电脑 | Python 环境兼容、个人学习 |
| Docker 运行 Community Edition | 需要 Docker | 当前电脑或自己的服务器 | 环境隔离、便于迁移和复现 |
| 服务器自托管 | 是 | 团队服务器 | 内网协作、数据自主控制 |

三种方式使用的核心标注概念一致，但部署责任不同：

```text
SaaS：官方维护运行环境，用户管理项目和数据
pip：用户维护 Python、依赖、数据库和数据目录
Docker：用户维护容器、持久化目录和端口
```

本课程后续要导入模拟数据并练习标注，三种方式都能完成。如果不希望安装软件，可以直接使用
SaaS；如果希望数据保留在本机并掌握部署过程，优先使用 Docker。

官方当前提供 Community、Starter Cloud 和 Enterprise 三种版本，功能差异可查看
[版本对比](https://labelstud.io/guide/label_studio_compare.html)。课程学习不依赖 Enterprise 专属
功能，Community Edition 足够完成后续案例。

先在终端检查环境，不要一上来就安装：

```bash
python3 --version
docker --version
docker info
```

三条命令分别回答：

- 是否安装 Python，以及版本是多少；
- 是否安装 Docker 命令行；
- Docker 后台服务是否已经运行。

截至本节编写时，本机检查结果为：

```text
Python：3.14.5
Docker CLI：28.3.2
Label Studio 命令：尚未安装
Docker 后台服务：尚未启动
```

官方 `pip` 安装步骤要求 Python 3.8 或更高版本，但“高于最低版本”并不保证所有依赖已经适配
最新 Python。Python 3.14 较新，如果某些依赖暂时没有兼容的安装包，`pip` 可能需要本地编译或
直接失败。

因此，这台机器的推荐路线是：

```text
启动 Docker Desktop
  ↓
确认 docker info 成功
  ↓
用 Docker 运行 Label Studio
```

如果希望使用 `pip`，建议另外创建一个使用成熟 Python 版本的隔离环境，不要把依赖直接安装到
系统 Python 中。

### 2. 推荐方案：使用 Docker 安装

第一步，启动 Docker Desktop。macOS 可以从“应用程序”中打开，也可以运行：

```bash
open -a Docker
```

等待菜单栏中的 Docker 显示运行正常，然后验证：

```bash
docker info
```

如果不再出现 `Cannot connect to the Docker daemon`，说明后台服务已经启动。

第二步，创建独立实验目录：

```bash
mkdir -p label-studio-lab/data
cd label-studio-lab
```

第三步，启动容器：

```bash
docker run --name label-studio \
  -it \
  -p 8080:8080 \
  -v "$(pwd)/data:/label-studio/data" \
  heartexlabs/label-studio:latest
```

各参数的含义是：

| 参数 | 作用 |
| --- | --- |
| `--name label-studio` | 给容器一个固定名称，方便以后再次启动 |
| `-it` | 在当前终端显示运行日志，按 `Ctrl+C` 可以停止 |
| `-p 8080:8080` | 将本机 8080 端口映射到容器 8080 端口 |
| `-v ...:/label-studio/data` | 把数据库和上传文件保存到当前目录的 `data` 中 |
| `heartexlabs/label-studio:latest` | 使用官方 Community Edition 镜像 |

首次运行需要下载镜像，耗时取决于网络。日志显示服务启动后，在浏览器访问：

```text
http://localhost:8080
```

在学习环境中使用 `latest` 可以快速获得当前版本；生产环境应固定经过验证的镜像版本或摘要，
避免重建容器时意外升级。

停止容器后，下一次不要重复执行 `docker run --name label-studio`，否则会提示名称已经存在。重新
启动原容器即可：

```bash
docker start -a label-studio
```

`-a` 会把容器日志附加到当前终端。不想附加日志时，可以运行：

```bash
docker start label-studio
```

### 3. 首次登录与安装验证

第一次打开 `http://localhost:8080` 时，按照页面提示创建本地账号。Community Edition 中创建的
账号保存在当前 Label Studio 服务中，并不是 Label Studio Cloud 账号。

登录后先完成一个最小验证：

1. 页面能够正常打开；
2. 可以创建一个名为 `installation-check` 的空项目；
3. 关闭并重新启动服务后，项目仍然存在；
4. 浏览器刷新后没有出现静态资源加载错误。

也可以从终端检查容器和 HTTP 服务：

```bash
docker ps --filter name=label-studio
curl -I http://localhost:8080
```

判断标准：

- `docker ps` 能看到 `label-studio`，状态为运行中；
- `curl` 能收到 HTTP 响应，`200` 或登录跳转响应都说明服务可访问；
- `data` 目录中已经产生数据库等运行数据；
- 重启容器后项目没有消失。

最后一项非常重要，它证明挂载目录真正实现了数据持久化，而不只是“页面当前能打开”。

### 4. 备选方案：使用 pip 安装

如果 Python 版本和依赖兼容，可以在独立虚拟环境中安装：

```bash
python3 -m venv .venv-label-studio
source .venv-label-studio/bin/activate
python -m pip install --upgrade pip
python -m pip install label-studio
```

安装完成后检查版本并启动：

```bash
label-studio version
label-studio start
```

然后访问：

```text
http://localhost:8080
```

以后重新进入环境时，需要先激活虚拟环境：

```bash
source .venv-label-studio/bin/activate
label-studio start
```

使用完毕可以按 `Ctrl+C` 停止服务，再退出虚拟环境：

```bash
deactivate
```

如果在 Python 3.14 上遇到依赖无法安装，不要使用 `sudo pip install` 强行写入系统环境。更稳妥的
处理方式是换用兼容性更成熟的独立 Python 环境，或者直接使用本节的 Docker 方案。

官方也提供 Homebrew 安装方式：

```bash
brew tap humansignal/tap
brew install humansignal/tap/label-studio
label-studio
```

Homebrew 操作更简短，但从课程学习角度看，Python 虚拟环境更容易理解依赖边界，Docker 则更
容易保证环境隔离。三种方式选一种即可，不需要重复安装。

### 5. 零安装方案：直接使用 SaaS

不想维护本地服务时，可以选择 Starter Cloud 或 Enterprise Cloud。基本流程是：

```text
注册云端账号
  ↓
创建项目
  ↓
配置标注界面
  ↓
导入课程数据
  ↓
开始标注并导出结果
```

SaaS 的优点是不需要处理 Python、Docker、端口和本地数据库，也方便多人访问。需要承担的成本
是版本功能和配额受服务方案限制，并且数据会由云端平台处理。

上传数据前应先判断：

- 数据是否包含个人信息、公司内部信息或客户资料；
- 所在组织是否允许把数据上传到第三方云服务；
- 是否需要特定地区存储、访问审计或删除证明；
- 测试数据能否换成脱敏或人工构造的样本。

本课程后续使用模拟数据时可以选择 SaaS；处理真实敏感数据时，不能因为“只是做实验”就跳过
隐私和合规检查。

### 6. 数据持久化与安全边界

Docker 容器内部的文件系统可以随着容器删除而消失，所以启动命令中的目录挂载不是可选装饰：

```text
本机 ./data
      ⇅ 挂载
容器 /label-studio/data
```

项目、账号、标注任务和上传资源会通过该目录持久化。即使停止或替换容器，只要挂载目录和数据
结构仍然有效，就可以保留状态。官方对 Docker 持久化的说明见
[数据库与持久化文档](https://labelstud.io/guide/storedata)。

需要区分三类数据：

| 数据 | 常见位置 | 是否需要备份 |
| --- | --- | --- |
| 项目与标注记录 | SQLite 或 PostgreSQL | 需要 |
| 上传的图片、音频等资源 | 上传目录、对象存储或外部 URL | 需要或保证来源持续可用 |
| 导出的结果文件 | 用户选择的导出目录 | 需要 |

本地学习可以使用 SQLite；多人生产环境通常需要更完整的数据库、备份和恢复方案。不要把“已经
导出一次 JSON”等同于完成了整个服务的备份。

安全方面还要遵守几个基本边界：

- 本地学习时不要把 8080 端口直接暴露到公网；
- 不要在公开仓库提交账号密码、API Key 或真实敏感数据；
- 团队部署应使用 HTTPS、访问控制、备份和经过评审的网络配置；
- 生产部署应按照官方[安全指南](https://labelstud.io/guide/security.html)设置安全选项，而不是
  直接复制学习环境命令上线。

### 7. 常见问题与排查顺序

| 现象 | 常见原因 | 排查方法 |
| --- | --- | --- |
| `Cannot connect to the Docker daemon` | Docker Desktop 未启动 | 启动 Docker，再运行 `docker info` |
| 8080 端口被占用 | 其他服务正在监听 8080 | 检查端口，或映射到 9001 |
| 容器名称已存在 | 已经创建过同名容器 | 使用 `docker start label-studio` |
| Docker 挂载目录无权限 | 容器用户不能写入宿主机目录 | 检查目录所有者和写权限 |
| `pip` 安装依赖失败 | Python 版本或编译依赖不兼容 | 使用干净虚拟环境或改用 Docker |
| 重启后项目消失 | 没有正确挂载持久化目录 | 检查 `-v` 参数和实际数据目录 |
| 页面可以打开但资源加载失败 | 主机地址、代理或协议配置错误 | 先用本机 `localhost` 验证，再检查 Host 配置 |

检查端口占用：

```bash
lsof -nP -iTCP:8080 -sTCP:LISTEN
```

如果 8080 已被其他程序使用，可以把本机端口改为 9001，容器内部仍然保持 8080：

```bash
docker run --name label-studio \
  -it \
  -p 9001:8080 \
  -v "$(pwd)/data:/label-studio/data" \
  heartexlabs/label-studio:latest
```

此时访问 `http://localhost:9001`。Label Studio 默认端口和自定义端口方式可查阅
[官方启动文档](https://labelstud.io/guide/start)。

排查时按照“进程 → 端口 → HTTP → 登录 → 持久化”的顺序逐层检查：

```text
Docker 是否运行？
  ↓
容器是否运行？
  ↓
端口是否映射？
  ↓
浏览器是否收到响应？
  ↓
账号能否登录？
  ↓
重启后数据是否仍在？
```

### 本节练习

1. 根据场景选择方案：

   - 只想用模拟数据快速体验，不想安装软件：SaaS；
   - 本机 Python 很新，希望避免依赖冲突：Docker；
   - 需要理解 Python 包并且已有兼容的隔离环境：`pip`；
   - 公司敏感数据不允许离开内网：经过安全评审的自托管部署。

2. 解释下面 Docker 参数为什么不能轻易删除：

```bash
-v "$(pwd)/data:/label-studio/data"
```

合格答案：它把容器中的 Label Studio 数据目录映射到宿主机，保证容器停止或替换后仍有机会恢复
项目和标注记录。

3. 完成安装后执行最小验收：

```text
[ ] 可以访问登录页
[ ] 可以创建 installation-check 项目
[ ] 可以停止并重新启动服务
[ ] 重启后项目仍然存在
[ ] 知道当前数据目录在哪里
```

只有五项都完成，才能说明学习环境不仅“启动过”，而且具备继续实验所需的持久化能力。

### 本节小结

Label Studio 可以通过 SaaS、`pip` 或 Docker 使用，不要求必须本地安装。对于当前这台 Python
3.14.5、已有 Docker CLI 的 macOS 机器，优先使用 Docker 更容易隔离依赖，但需要先启动 Docker
Desktop。

推荐的学习路径可以压缩成四步：

```text
启动 Docker
  ↓
挂载本地数据目录并运行官方镜像
  ↓
访问 localhost:8080 并创建账号
  ↓
重启容器，验证项目仍然存在
```

安装成功的标准不是“终端没有报错”，而是页面可访问、项目可创建、服务可重启、数据可持久化。
